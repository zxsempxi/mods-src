# План разработки: мод «Тактический инвентарь» (Minecraft NeoForge 1.21.1)

> Документ для Claude Code. Работай строго по этапам, по одному этапу за раз.
> После каждого этапа: сборка (`./gradlew build`), запуск `runClient`/`runServer`, проверка критериев приёмки, коммит.
> Не переходи к следующему этапу, пока текущий не проходит критерии приёмки.
> Если решение не описано в этом документе — спроси пользователя, не додумывай.

---

## 0. Контекст и цель

Мод в стиле Escape from Tarkov / DayZ: дополнительное место для предметов дают надетые вещи.

- Каждая часть брони (шлем, нагрудник = «разгрузка», поножи, ботинки) — **контейнер**: даёт сетку слотов, размер зависит от материала.
- Ванильный инвентарь (27 + хотбар 9) **не урезается**, только переносится в новой раскладке экрана.
- Есть отдельные слоты **рюкзака** (Sophisticated Backpacks) и **элитр**.
- **Trash-слот** как в Террарии.
- Крафт 2×2 есть, **книги рецептов нет**.
- Показатели (HP, голод, броня, опыт, воздух) переносятся в экран инвентаря, с HUD скрываются; при низком HP — **красная виньетка и сердцебиение**.
- При открытии сундука — «режим лута»: контейнер справа, экипировка и хранилища слева.

## 1. Зафиксированные решения

| Вопрос | Решение |
|---|---|
| Где хранятся вещи брони | **Внутри предмета брони** (data component `ItemContainerContents`). Снял броню — вещи остаются в ней. Выпадает при смерти целиком. |
| Ванильный инвентарь | Не трогаем по размеру (36 слотов), только позиция в GUI |
| Книга рецептов | Убрана из экрана |
| Стат-бары на HUD | Скрыты (переключатель в конфиге), вместо них виньетка + сердцебиение |
| Слоты рюкзака и элитр | Через **Curios API** (слот `back` для рюкзака — SB его уже поддерживает; свой слот `elytra`) |
| Рюкзак + элитры одновременно | Разрешены оба (по умолчанию); в конфиге опция взаимоисключения. При полёте рюкзак не рендерится (опция) |
| Креатив | Ванильный экран инвентаря без изменений |
| Сервер | Все изменения предметов — только на сервере. Клиент шлёт запросы, сервер валидирует |

> ⚠️ Два последних пункта про Curios и рюкзак+элитры приняты по умолчанию — пользователь их ещё не подтвердил. Перед этапом 4 уточни у пользователя.

## 2. Технический стек

- Minecraft **1.21.1**, **NeoForge** (последняя стабильная 21.1.x)
- Java **21**
- Шаблон: официальный NeoForge MDK для 1.21.1 (ModDevGradle)
- Mojang mappings (+ Parchment, если удобно)
- Зависимости:
  - **Curios API** (обязательная) — maven `https://maven.theillusivec4.top/`
  - **Sophisticated Backpacks** + **Sophisticated Core** (опциональная, только для интеграции; `compileOnly` + runtime в dev) — проверь актуальный maven/Curse Maven
  - **EMI** и/или **JEI** (опционально, для зон исключения GUI)
- Конфиг: `ModConfigSpec` (NeoForge), клиентский + серверный
- Актуальные версии всех зависимостей **проверяй сам** перед добавлением, не угадывай.

**modid:** `gearinventory` (временное — уточни у пользователя название перед публикацией).

## 4. Этапы

### Этап 0 — Каркас
**Задачи**
- Сгенерировать проект из NeoForge MDK 1.21.1, настроить modid, mods.toml (`neoforge.mods.toml`), миксины.
- Зарегистрировать `GearInventoryMenu` (`MenuType`), пустой `GearInventoryScreen`.
- Клиент: в выживании/приключении перехватить открытие инвентаря (E) → отправить `OpenGearInventoryPayload` → сервер открывает меню. Креатив — ванилла.
- Перенести в меню ванильные слоты: броня (4), щит, инвентарь 27, хотбар 9 (ссылки на `player.getInventory()`).

**Критерии приёмки**
- По E в выживании открывается наш экран со всеми ванильными слотами, предметы перемещаются, shift-клик работает между инвентарём и хотбаром.
- В креативе — ванильный экран.
- Работает на выделенном сервере без рассинхрона.

### Этап 1 — Хранилище в броне
**Задачи**
- `ArmorStorage`: хранение содержимого в `DataComponents.CONTAINER` (или свой компонент, если ванильный конфликтует с другими модами — реши и объясни выбор).
- Data map `gearinventory:armor_storage` (item → `{width, height}`), дефолтный датапак:

| Материал | Голова | Разгрузка | Поножи | Ботинки |
|---|---|---|---|---|
| Кожа | 1×1 | 2×2 | 3×2 | 1×2 |
| Кольчуга | 2×1 | 3×2 | 4×2 | 2×2 |
| Железо / золото | 2×2 | 4×3 | 6×3 | 3×2 |
| Алмаз / незерит | 2×2 | 5×3 | 6×4 | 3×3 |
| Черепаший панцирь | 1×1 | — | — | — |

- Фолбэк для модовой брони без записи: по тегу/конфигу (по умолчанию 0 слотов).
- `ArmorGridSlot` — слот, привязанный к надетому стаку брони и индексу. При смене брони слоты пересобираются (меню переоткрывается или слоты становятся неактивными — выбери надёжный вариант, без дюпов).
- Отрисовка секций «ГОЛОВА / РАЗГРУЗКА / ПОНОЖИ / БОТИНКИ» в колонке справа, пустая броня — заглушка «нет разгрузки».
- Тултип брони: «Вместимость: 4×3, занято 7/12».

**Критерии приёмки**
- Положил вещи в разгрузку, снял нагрудник, надел снова — вещи на месте.
- Выбросил нагрудник на землю, подобрал другой игрок — вещи у него.
- Перезаход в мир/рестарт сервера — содержимое сохраняется.
- Нельзя положить броню с содержимым в её же хранилище.

### Этап 2 — Раскладка обычного режима
**Задачи**
- Реализовать раскладку:
```
┌───────────────────────────────────────────────────────────────┐
│ [ШЛЕМ]  [РЮКЗАК] ┌───────┐  [КРАФТ 2×2] → [■]  │ ГОЛОВА      │
│ [ГРУДЬ] [ЭЛИТРЫ] │модель │                     │ РАЗГРУЗКА   │
│ [НОГИ]  [ЩИТ]    │игрока │  [🗑 TRASH]          │ ПОНОЖИ      │
│ [БОТИН]          └───────┘                     │ БОТИНКИ     │
│ ИНВЕНТАРЬ 9×3                                  │ РЮКЗАК      │
│ ХОТБАР 9                                       │ (скролл ↕)  │
├───────────────────────────────────────────────────────────────┤
│ ❤ HP   🍗 голод   🛡 броня   ✦ ур. + полоса опыта   💧 воздух │
└───────────────────────────────────────────────────────────────┘
```
  (слоты рюкзака/элитр/корзины — пока заглушки, оживают в этапах 3–4)
- Колонка хранилищ со скроллом (колесо мыши, ползунок), корректный hit-test слотов при прокрутке.
- Shift-клик: инвентарь/хотбар ↔ хранилища брони; броня из инвентаря → в слот брони.
- Порядок переноса настраивается в конфиге.

**Критерии приёмки**
- Работает на GUI scale 2, 3, 4 и на 1080p/1440p; ничего не перекрывается.
- Shift-клик не теряет и не дублирует предметы.

### Этап 3 — Корзина и крафт 2×2
**Задачи**
- `TrashAttachment` (data attachment на игроке, сохраняется между заходами; при смерти очищается — не копировать на нового игрока).
- Поведение как в Террарии: положенный предмет остаётся в корзине, пока его не вытеснит следующий; можно забрать обратно.
- Ctrl+клик по любому слоту → предмет в корзину (пакет `TrashItemPayload`, валидация на сервере).
- Крафт 2×2: `CraftingContainer` + `ResultSlot`, без кнопки книги рецептов. При закрытии экрана предметы из сетки возвращаются игроку.

**Критерии приёмки**
- Предмет в корзине переживает перезаход; вытесняется следующим; Ctrl+клик работает.
- Крафт 2×2 работает, книги рецептов нет, предметы из сетки не теряются.

### Этап 4 — Слоты рюкзака и элитр (Curios)
> Перед началом: подтверди у пользователя Curios как обязательную зависимость и правило «рюкзак + элитры».

**Задачи**
- Зарегистрировать Curios-слот `elytra` (иконка, валидатор: только элитры/предметы с тегом `gearinventory:elytra_like`). Использовать существующий слот `back` для рюкзака.
- `CurioProxySlot` — отображение этих Curios-слотов в нашем меню. Спрятать стандартную кнопку Curios в нашем экране.
- Запретить элитры и рюкзак в нагрудном слоте (нагрудник = разгрузка).
- Элитры: миксины, чтобы старт/поддержание полёта, износ, Mending/Unbreaking и рендер (`ElytraLayer`) брали элитры из нашего слота, а не только из нагрудного.
- Sophisticated Backpacks (если установлен):
  - Проверить, что клавиша B и апгрейды (pickup, magnet, feeding и т.д.) видят рюкзак в слоте `back`.
  - Секция «РЮКЗАК» в колонке: иконка, тир, кнопка «Открыть» (открывает экран SB).
  - Порядок подбора: pickup-апгрейд рюкзака → ванильный инвентарь → хранилища брони.
- Конфиг: взаимоисключение рюкзака и элитр; скрытие модели рюкзака в полёте.

**Критерии приёмки**
- Полёт на элитрах из слота работает, элитры изнашиваются и чинятся Mending, рендерятся на игроке.
- Рюкзак SB в слоте: B открывает, апгрейды работают, при смерти выпадает (и совместим с модами могил через Curios).
- Без установленного SB мод грузится и работает (слот рюкзака просто принимает предметы с тегом/ничего).

### Этап 5 — Режим лута (сундуки)
**Задачи**
- Миксины в конструкторы ванильных меню хранения: `ChestMenu` (сундук, большой сундук, бочка, эндер-сундук), `ShulkerBoxMenu`, `HopperMenu`, `DispenserMenu`. Добавлять слоты хранилищ брони **в конец** списка слотов, одинаково на сервере и клиенте.
- Переопределить `quickMoveStack` для этих меню: контейнер → инвентарь → хранилища брони; игрок → контейнер.
- Клиент: подмена/расширение экранов этих меню на раскладку:
```
┌ ЭКИПИРОВКА ──────┬ ХРАНИЛИЩА (скролл) ─┬ КОНТЕЙНЕР ──────────────┐
│ [шлем]   [рюкзак]│ ГОЛОВА              │ ▢▢▢▢▢▢▢▢▢ (до 9×6)      │
│ [грудь]  [элитры]│ РАЗГРУЗКА           │                         │
│ [ноги]   [щит]   │ ПОНОЖИ              │ [Забрать всё]           │
│ [ботинки][🗑]    │ БОТИНКИ             │ [Сложить всё]           │
├──────────────────┴─────────────────────┤ [Сортировать]           │
│ ИНВЕНТАРЬ 9×3 + ХОТБАР                 │                         │
├────────────────────────────────────────┴─────────────────────────┤
│ полоса статов                                                     │
└───────────────────────────────────────────────────────────────────┘
```
  Модель игрока и крафт 2×2 в режиме лута скрыты.
- Если ширины не хватает (узкий экран / большой GUI scale) — колонка хранилищ сворачивается во вкладки.
- Кнопки «Забрать всё» / «Сложить всё» (как в Террарии: сложить — только те предметы, что уже есть в контейнере) / «Сортировать» — серверные пакеты.
- Верстак, печь, наковальня и модовые контейнеры — в v1 без изменений (только ванильный инвентарь). Подготовить белый список для будущих модовых меню.

**Критерии приёмки**
- Нет рассинхрона индексов слотов между клиентом и сервером (проверить на выделенном сервере с задержкой).
- Shift-клик, кнопки и Ctrl+клик в корзину работают в режиме лута.
- Шалкер нельзя положить в разгрузку, если внутри разгрузка с вещами (и наоборот) — вложенность запрещена.

### Этап 6 — Статы, HUD, виньетка, сердцебиение
**Задачи**
- Полоса статов внизу экрана: HP (с учётом поглощения), голод/насыщение, броня, уровень + полоса опыта, воздух (только под водой).
- Скрытие ванильных слоёв HUD через `RenderGuiLayerEvent.Pre`: `PLAYER_HEALTH`, `FOOD_LEVEL`, `ARMOR_LEVEL`, `EXPERIENCE_BAR`, `EXPERIENCE_LEVEL`, `AIR_LEVEL` (переключатель в клиентском конфиге).
- Виньетка: текстура красного градиента по краям, порог из конфига (по умолчанию HP ≤ 30%), интенсивность растёт с падением HP, пульсирует в такт сердцебиению, плавно затухает при восстановлении, короткая вспышка при получении урона.
- Сердцебиение: свой `SoundEvent` (`gearinventory:heartbeat`), интервал от ~1.0 с на пороге до ~0.4 с при 1–2 HP, без наложения, громкость в конфиге.
- Звук: нужен свой .ogg (CC0/собственный) — **спроси пользователя**, есть ли файл; до этого используй заглушку.

**Критерии приёмки**
- Ванильные бары скрыты, в инвентаре показатели корректны и обновляются в реальном времени.
- Виньетка и звук включаются/выключаются по порогу, не мерцают на границе (гистерезис ~1 HP).

### Этап 7 — Защита от абуза и крайние случаи
- Смена брони правым кликом из руки — вещи уезжают вместе с бронёй, без дюпа.
- Раздатчик надевает броню — корректно.
- Броня с вещами: запрет вложения в шалкеры, бандлы, рюкзаки SB, собственные хранилища.
- Смерть: броня с вещами выпадает целиком; `keepInventory` уважается; совместимость с модами могил.
- Поломка брони при износе: содержимое выпадает на землю у игрока (настраивается).
- Смена измерения, респаун, `/clear`, `/give` — без потерь и дюпов.
- Сервер отклоняет любые пакеты при неоткрытом меню / несоответствии состояния.

### Этап 8 — Совместимость
- EMI/JEI: зоны исключения, чтобы панель предметов не перекрывала колонки (на скриншоте пользователя стоит EMI справа).
- Ганмод из сборки пользователя: **выяснить у пользователя, какой именно**. Задача: чтобы патроны/магазины в хранилищах брони были видны для перезарядки (через API ганмода или миксин в его поиск патронов). Без этого патроны работают только из ванильного инвентаря.
- Sophisticated Backpacks: проверить режим лута при открытом рюкзаке (рюкзак — модовое меню, ванильная раскладка).

## 5. Правила для реализации

1. **Сервер — источник истины.** Любое перемещение предметов выполняется и проверяется на сервере.
2. **Минимум миксинов.** Сначала ищи событие NeoForge; миксин — только если события нет. Каждый миксин — с комментарием, зачем он нужен.
3. Ванильный `Inventory` по размеру не менять.
4. Логику (хранилище, сортировка, порядок подбора) держать отдельно от GUI и миксинов — так проще портировать на новые версии.
5. Все размеры/пороги — в конфиге или датапаке, не хардкодить.
6. После каждого этапа — короткий отчёт пользователю: что сделано, что проверено, что не получилось.
